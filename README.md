# AI Fix Runner

AI Fix Runner is a local-only web application that evaluates automated code repair ("AI fix") workflows on the developer's machine. It copies broken repos into temporary workspaces, runs their tests, applies repair patches generated by a repair engine, and proves the fix by rerunning tests — all locally.

## Local Mode

This Test 1 version is intentionally local-only. It is designed so the **runner** can later be swapped with **Tensorlake Sandbox** in Test 2 without rewriting the whole application.

## Architecture

```
+-----------+        +-----------+        +-------------+
|  Frontend |------->|  Backend  |------->| LocalRunner |----> child_process.spawn
|  (React)  |        | (Express) |        +-------------+
+-----------+        +-----------+        | PatchApplier|----> fs.writeFile
                                          +-------------+
                                          |RepairEngine |----> FixtureRepairEngine (deterministic)
                                          +-------------+
```

Key interfaces:

- **Runner**: `prepareWorkspace`, `runCommand`, `readFile`, `writeFile`, `listFiles`, `cleanup`
- **PatchApplier**: `applyPatch` (validates paths, prevents traversal)
- **RepairEngine**: `proposePatch` (returns structured file replacements)

To replace with Tensorlake in Test 2, swap `LocalRunner` with `TensorlakeRunner` implementing the same `Runner` interface.

## Built-in Fixtures

Three broken TypeScript repos ship with the app. Each has tests that fail initially and pass after the repair engine applies the correct patch.

| Fixture | Bug | File Patched |
|---|---|---|
| `invoice-calculator-bug` | Tax before discount, early rounding, missing validation | `src/calculateInvoice.ts` |
| `markdown-parser-bug` | Treats sentence hyphens as list items, breaks code blocks | `src/parser.ts` |
| `todo-api-bug` | PATCH returns stale data, no `completed` validation, empty title accepted | `src/app.ts` |

## Safety Limitations (Local Mode)

- This is a **local demo**, not a secure sandbox.
- Commands run with `child_process.spawn` (no `shell: true`), but package scripts from the repo still execute on your machine.
- Max stdout/stderr per command is capped (default 200 KB).
- Only predefined commands run by default; arbitrary shell strings from the frontend are rejected.
- Custom repo paths are disabled unless `ALLOW_CUSTOM_REPO_PATHS=true`.
- Do not use with untrusted repos.

## Environment Variables

Copy `.env.example` to `.env` and adjust:

```bash
PORT=8787
DATABASE_URL=./data/ai-fix-runner.sqlite
WORKSPACE_ROOT=./tmp/workspaces
UPLOAD_ROOT=./tmp/uploads
KEEP_WORKSPACES=false          # Set true to keep temp dirs for debugging
ALLOW_CUSTOM_REPO_PATHS=false  # Set true to allow arbitrary local paths
MAX_STDIO_BYTES=200000
```

## Custom Repo Support

Two modes are supported:

1. **Local path** — disabled by default (`ALLOW_CUSTOM_REPO_PATHS=false`).
2. **Upload zip** — frontend allows uploading a `.zip`; backend extracts safely with path-traversal checks.

For custom repos, the built-in `NoopRepairEngine` explains that no real LLM is configured. The app still runs install, test, and build commands and shows full logs.

## API Examples

```bash
# Health
curl http://localhost:8787/health

# List fixtures
curl http://localhost:8787/api/fixtures

# Start a run
curl -X POST http://localhost:8787/api/runs \
  -H "Content-Type: application/json" \
  -d '{
    "source": {
      "type": "fixture",
      "fixtureId": "invoice-calculator-bug"
    },
    "maxAttempts": 3,
    "commands": {
      "install": ["npm", "install"],
      "test": ["npm", "test"],
      "build": ["npm", "run", "build"]
    },
    "runBuildAfterTestsPass": true
  }'

# Get run result
curl http://localhost:8787/api/runs/<runId>

# List recent runs
curl http://localhost:8787/api/runs
```

## Manual Fixture Verification

Each fixture can be verified independently before running through the app:

```bash
cd fixtures/invoice-calculator-bug && npm install && npm test   # expect failures
cd fixtures/markdown-parser-bug  && npm install && npm test   # expect failures
cd fixtures/todo-api-bug         && npm install && npm test   # expect failures
```

After applying the built-in repair patch (replace the buggy file with its fixed version), all tests should pass.

## How TensorlakeRunner Can Replace LocalRunner

`LocalRunner` implements the `Runner` interface in `apps/api/src/runner/local.ts`. To switch to Tensorlake:

1. Create `apps/api/src/runner/tensorlake.ts`
2. Implement `Runner` using Tensorlake Sandbox SDK
3. Replace `new LocalRunner()` with `new TensorlakeRunner()` in `apps/api/src/routes/runs.ts`

No changes needed to the repair loop, patch applier, or frontend.

## What's Stubbed / Incomplete

- **Real LLM repair engine**: `NoopRepairEngine` handles all non-fixture repos. Replace it with a real model client in Test 2 or a later version.
- **WebSocket live streaming**: The frontend polls every 1.5s. WebSockets could be added for true real-time logs.
- **Frontend tests**: Not included.
- **Secure sandbox**: Local mode is intentionally not a sandbox; use only with trusted repos.
